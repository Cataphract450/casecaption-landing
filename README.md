# CaseCaption Landing

Статический лендинг для Product Radar, холодных сообщений и первых разговоров.

Текущий публичный оффер:

```text
Один раз настраиваем шаблоны. Каждый следующий комплект — за несколько минут
```

Фокус лендинга:

- один закрывающий процесс до первого клиента, а не вся платформа;
- разовая настройка до трёх шаблонов за 5 рабочих дней;
- после настройки — прошлый выпуск, только новые условия из письма/PDF/DOCX,
  проверка изменений и договор + счёт + акт + ZIP;
- первый пилот `29 000 ₽`: `14 500 ₽` на старте и остаток после двух самостоятельных выпусков;
- первый тест только на обезличенном примере;
- без обещаний заменить `1C`, ЭДО или бухгалтерию.
- клиентский сотрудник сам выпускает комплект через CaseCaption после настройки.

## Готовность перед публикацией

1. CTA уже ведут в Telegram: `https://t.me/Igorigoryyy`.
2. HTML ожидает свежие бинарные ассеты:
   - `assets/casecaption-demo-closing-pack-2026-07.mp4`;
   - `assets/casecaption-demo-closing-pack-2026-07-poster.jpg`;
   - `assets/casecaption-og-closing-pack-2026-07.jpg`.
3. Финальный live-кандидат длится `60,7` секунды: реальный внешний разбор без fallback,
   `13` полей восстановлено из прошлого выпуска, `7/7` изменений подтверждено
   (`6` одним действием, `1` отдельно), ручной перенос не понадобился.
4. Все три файла записаны и проверены в браузере на `1440×900`, `1366×768`,
   `768×1024` и `390×844`; MP4 загружается и воспроизводится без ошибок.
5. Публичный URL: `https://cataphract450.github.io/casecaption-landing/`.
6. Старые `casecaption-demo-workspace.mp4` и `casecaption-demo-poster.jpg` больше не являются публичным доказательством текущего продукта.

## Быстрая публикация

Текущий публичный вариант опубликован отдельным репозиторием `Cataphract450/casecaption-landing`, чтобы не открывать основной private-репозиторий проекта.

### GitHub Pages

1. Закоммитить `landing/` и `.github/workflows/deploy-landing-pages.yml` в ветку `main`.
2. Запушить `main` в GitHub.
3. В GitHub открыть `Settings -> Pages`.
4. В поле `Source` выбрать `GitHub Actions`.
5. Открыть вкладку `Actions` и дождаться workflow `Deploy landing to GitHub Pages`.
6. После успешного деплоя GitHub покажет публичный URL вида `https://<account>.github.io/<repo>/`.

Если Pages уже включен через другой источник, переключить его на `GitHub Actions`, иначе новый workflow не станет источником публикации.

### Cloudflare Pages

1. Создать проект Pages из GitHub-репозитория.
2. Build command оставить пустым.
3. Output directory указать `landing`.
4. После деплоя заменить ссылку в Product Radar и outreach-сообщениях.

## Проверка перед Product Radar

- CTA ведет на реальный Telegram: `@Igorigoryyy`.
- Публичный URL: `https://cataphract450.github.io/casecaption-landing/`.
- Свежее демо открывается без авторизации в блоке `#result`, читается в обычном размере и на весь экран.
- Видео, poster и OG-картинка показывают текущий путь `готовый сценарий + 3 шаблона -> прошлый выпуск + новые условия -> проверка -> договор + счёт + акт + ZIP`.
- На `1440x900`, `1366x768`, `768x1024` и `390x844` нет горизонтального скролла.
- На первом экране одновременно понятны результат за минуты, разовая настройка за 5 рабочих дней, цена и CTA.
- В тексте нет старого обещания про «предыдущую версию» и ссылок на старое демо.
- В тексте нет обещаний "заменяем 1С", "любой формат", "полный документооборот".
- Первый экран не продает AI как главный аргумент.
- Цена и scope пилота одинаковы в hero, секции пилота и outreach-материалах.
- До CTA на реальные документы объяснены обезличивание, явное согласие на внешнюю модель и отдельное согласование хранения/удаления.
- Клавиатурный focus виден на ссылках, кнопках и видеоплеере.
